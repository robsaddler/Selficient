# Threat model: installable app and offline (M7)

*30 October 2026. Written before the code.*

## What it is

A web manifest, an install prompt (with the iOS how-to, since Safari never asks), and a service worker generated by the server from a template: the precache list is every static asset on disk and the version is a fingerprint of them, so nothing is hand-maintained and every deploy rolls clients forward. Pages are network-first with a cached fallback; code is network-first stamped with the release it came from; libraries and fonts are cache-first; tiles are cache-first; every other API route is never cached. The plan page, which is a POST, is kept for offline by storing the last successful plan response under the plan address, so a household can open their plan in a power cut with no signal.

## Assets

- Correctness over time: a device must never run one deploy's modules against another deploy's pages, and must never show a stale plan as if it were fresh.
- Honesty: offline must say it is offline and show only what is really available.
- Privacy: the cached plan page is personal; it lives in the browser's own cache for this origin, like the IndexedDB profile, and nowhere else.
- The server: the worker's fetch handler must never turn into an amplifier (retries in loops) or a way to hit uncacheable routes harder.

## Abuse and failure cases

| # | Case | Control | Test |
|---|---|---|---|
| 1 | The worker caches an API answer and serves it stale forever | `/api/*`, `/health` and the calendar download are never cached; the one exception is tiles, which the server declares immutable, and the tile status probe, which is network-first with a last-known fallback | `The_worker_never_caches_api_routes_except_tiles` |
| 2 | Build skew: a fresh page with stale modules, or the reverse | Pages carry the deploy fingerprint as `data-sw-build`; the worker answers `sw:version?` with its own; a mismatch reloads once, guarded to one reload per two minutes; code fetches are `no-cache` conditional requests stamped with the release they came from; a cached copy from another release never wins the slow-connection race | `Pages_carry_the_shell_fingerprint_the_worker_is_built_from`, JS review |
| 3 | A partially failed precache strands a device without an asset | Per-file, failure-tolerant precache; `fillShellGaps` on every activate and on every online page load | JS review |
| 4 | A new page's assets are not in the precache | The shell list is generated from disk, not written by hand; a test walks every asset the layout references and every file under the shell directories and asserts each is in the list | `The_shell_lists_every_static_asset` |
| 5 | The cached plan page is shown as if fresh, or shown to the wrong person | It is only served when the network fails; the page says so in a banner driven by the `offline` event; it lives in this browser's cache for this origin only, the same trust boundary as the IndexedDB profile (ADR-001) | `The_offline_page_and_banner_say_what_works` |
| 6 | The worker is served with a long cache lifetime and never updates | `/sw.js` is `Cache-Control: no-cache`; the browser re-checks it on navigation; `registration.update()` on every online load | `The_worker_is_served_fresh_every_time` |
| 7 | A hostile page on another origin registers or scopes our worker | Scope is `/` on our origin only; `Service-Worker-Allowed` is not widened; the manifest `id` and `scope` are fixed | `The_manifest_is_ours` |
| 8 | The template substitution injects something unexpected | Version and shell list are serialised as JSON, never string-concatenated; the template holds exactly two placeholders; a test asserts none remain | `The_worker_is_served_fresh_every_time` |
| 9 | The install prompt nags | Dismissal remembered thirty days per device, an install for good; nothing shown in standalone mode | JS review |

## Outcomes

*Adversarial pass, 30 October 2026, with the worker installed in Chrome against the local site.*

- Cases 1, 4, 6, 7 and 8 hold and are pinned by tests that read the served worker: the never-cache line, the tile exceptions, the two placeholders filled by JSON, `no-cache` on `/sw.js` and on the manifest, the manifest's `id`, `scope` and `start_url`, and a walk of every file under the shell directories and every asset the layout references against the precache list.
- Case 2 holds: the page's `data-sw-build` equals the worker's `VERSION` (pinned), the skew handshake and the `controllerchange` reload are guarded to one reload per two minutes and never over an open dialog or a field someone has typed into.
- Case 3 holds by construction, lifted unchanged from SiteWise: per-file precache, `fillShellGaps` on activate and on every online load. In Chrome the shell cache held all 40 entries (39 assets and the offline page) after the first load.
- Case 5: the plan POST is kept under `/plan` stamped with the release; in Chrome the runtime cache held the full plan page (hero and map included) after the re-post, and the offline page was in the shell cache. The banner follows the browser's own `online` and `offline` events and the `navigator.onLine` flag, so a synthetic event with the flag still true does not show it, which is right. A true offline reload is for the Playwright suite in M10, where the browser context can be set offline.
- Case 9 holds: dismissal remembered thirty days, install remembered for good, no button in standalone mode. In Chrome on the desktop the button appeared when the browser offered install, which it did on the second load.
- Found: `.webmanifest` had no content type in the framework's default map on this build, so the manifest was served as `application/octet-stream` until mapped. Pinned.
- Found: the layout test pinned `<html lang="en-GB">` exactly; the build attribute now lives on the element, and the test says so.
- Residual: the plan kept for offline is the last one built on this device, which may be older than the profile if the profile was imported from a file while offline. The next online load re-posts and replaces it. Accepted.
- Residual: Lighthouse's installability audit and the real offline reload are owed to M10 with Playwright.
