# Decisions and assumptions for Rob to review

*Started 31 October 2026, when Rob left for the day with "do it all; document assumptions and decisions I might want to review later". Each entry says what was decided, what the alternative was, and why; the ones marked **review** are the ones where his view could change the answer. Newest at the bottom.*

| # | Decision | Alternative not taken | Why | Review? |
|---|---|---|---|---|
| 1 | The platform database is SQL Server, reached through Dapper, with migrations as numbered scripts embedded in the Infrastructure assembly and recorded in `dbo.schema_versions` | SQLite (what M18 shipped); DbUp or FluentMigrator for the migrations | Rob has SQL Server licensed locally and on the VPS and runs SiteWise on it; a hand-rolled migrator is sixty lines, fully under test, and keeps the "Dapper, no ORM" rule with no new framework | No |
| 2 | Every test suite runs the real store against a real SQL Server: one database per test host, created and dropped by the test kit; a service container on the CI runner | Mocking the store in the Web tests; one shared test database | A mocked store would have hidden the `long`/`int` materialisation fault that SQLite found and SQL Server would have repeated; per-host databases cost about a second each and make the suites independent | No |
| 3 | The local test server is the default instance with integrated security; CI's is `mcr.microsoft.com/mssql/server:2025-latest` with an `sa` password composed from the run id and attempt | A named instance or LocalDB locally; a literal password in the workflow; a GitHub secret | "Secrets are environment variables, never in the repo, never in workflows" is a standing rule and a literal would have broken it, however throwaway. A value derived from the run is written nowhere, is never reused, and needs no secret to be managed; the server it opens lives for one job and is reachable from nothing else. SQL Server 2025 matches Rob's local build | **Review** if you would rather the CI image track 2022 |
| 4 | The vulnerable `System.Security.Cryptography.Pkcs` 9.0 that `Microsoft.Data.SqlClient` 7.1 still references is pinned centrally to 10.0.14 | Suppressing the NuGet audit warning | The audit is a gate, not a nuisance; a pin fixes the thing the warning is about | No |
| 5 | Migration is the first hosted service and runs to completion before the site answers; a failed migration fails the start | Migrating from the deploy workflow with a separate tool | One deployable, one secret, and the deploy's own health probe tells you it failed | No |
| 6 | The connection string is required at start; without it the host refuses to run, locally as well | Falling back to an in-memory or SQLite store when unset | A site that quietly runs on a different store than the vhost is the assumption this milestone exists to remove | No |
| 7 | The re-seed path is a manual `DELETE` in the runbook rather than an operator button | A "Start the catalogue again" hand on the reviewer | It throws away every check, click and reader's tip; a thing that destructive belongs behind the database login, not a cookie | **Review** |
| 8 | The Data Protection key ring lives in the database, wrapped by the machine's DPAPI on Windows (`protectToLocalMachine`) | The file system under the site folder; a certificate | A redeploy mirrors the site folder and would lose a file ring; machine-scope DPAPI survives an app-pool identity change where user scope does not; a certificate is the right next step if the site ever runs on more than one box | **Review** if a second web server is ever planned |
| 9 | The distributed cache behind `HybridCache` is a SQL Server table in the same database, with tiles kept in process only | Redis; no distributed cache | One licensed server already there; tiles are up to two megabytes from a file on the same disk, so the database would be a slower cache than the file | **Review** if a Redis is ever added for other reasons |
| 10 | `/health` stays a bare liveness "ok"; `/health/ready` answers "ready" or "not ready" and nothing else; the detail is on the reviewer behind the key | A JSON readiness report on the probe | An anonymous caller is owed the verdict, not the diagnosis; the deploy's probe now gates on readiness, so a site that starts without its database fails the deploy | No |
| 11 | OpenTelemetry traces and metrics, and the Serilog logs, leave only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; upstream spans are cut to their host before they leave | Always exporting to localhost; keeping full URLs on spans | Without a collector an exporter only fills a buffer and a log with connection failures; a span with the postcodes.io path on it carries a postcode, which the privacy page says never leaves the browser | **Review**: which collector (Seq, Grafana Cloud, Azure Monitor) you want on the VPS; nothing is chosen here |
| 12 | Every hand on the reviewer and every run of the worker is written to the database, without any identity | A log line only | The reviewer is the one authenticated surface, and "who hid this and when" has to outlive a fortnight of log files; the operator is one key, so a hand records what and when, never who | No |
| 13 | Load targets for the two new endpoints: the click counter at 200 a second with a p95 under 50 ms, the deals page at 50 a second under 100 ms | Leaving them out of the harness | A redirect that writes one row is the one write a household makes and must never queue; the deals page is the one shareable public page | No |
| 14 | The display face is re-subset with weight 300 to 800 and width 75% to 100% (it was 500 to 800 and 85% to 100%), from the Google Fonts build of Bricolage Grotesque, and the figure on the hero and the scenario cards is set at 300 and 75% as the design mockup drew it | Keeping the narrower subset and letting the browser fall back to 500 at 85%, which is what the site had been doing silently | The mockup Rob's users preferred is the light condensed figure at up to 11rem; the old subset could not draw it, so the site drew something heavier and smaller and nobody was told. The files are OFL, the same licence as before, and the subset is still Latin-1 only | **Review** the look on `/` and `/plan` in both themes |
| 15 | The key ring's SQL half is an Application port (`IKeyRingStore`) implemented in Infrastructure, with the Data Protection adapter and the DPAPI wrap in the web layer, and that one wiring method is excluded from coverage with a written justification | Letting Infrastructure reference `Microsoft.AspNetCore.DataProtection` | The architecture test forbids Infrastructure depending on ASP.NET Core, and the dependency rule is worth more than a shortcut; the excluded method is three lines whose guard runs one way per operating system | No |
| 16 | The click counter is write-behind: the hop increments a number in memory and a flusher writes the store once a second and once more when the host stops; the hop resolves the offer from the catalogue already in memory and touches no database | A row update per click (what M18 shipped); a queue | The load run put every scenario past its target because 200 clicks a second on one offer serialised on one row lock and queued the whole site behind the pool; a crash now loses at most the second not yet flushed, which is a trade a click counter should make. A hidden offer is a 404 at once because the snapshot reloads on every hand | **Review** if you ever want clicks to be exact to the last second |
| 17 | The deals are computed once per catalogue version and day and kept as objects in process, shared by everyone who asks while the read runs | `HybridCache`, which serialises what it keeps; a query per visitor | A pick is deliberately not a type that deserialises, and the public page must not run a grouped read of every check per visitor; a reload of the catalogue moves the version and so the key | No |
| 18 | The stylesheets are checked by stylelint (`stylelint-config-recommended`, with duplicate selectors and unknown at-rules on) as part of `npm run check`, which the gate runs | Leaving CSS unchecked, as it had been; adding a full style config with formatting rules | A doubled `@media@media` token, left by a bad substitution, made the browser drop the whole desktop hero block with no error anywhere, and the landing page served its phone column on a desktop until Rob looked at it. The recommended set catches the errors and leaves the house style alone; the four duplicate selectors it found were all accidental and are merged | No |
| 19 | Three E2E tests pin the landing hero's desktop layout: two columns at the mockup's seven-to-five split, the still life filling its column, and the figure at weight 300 and width 75% proved by measuring two spans rather than reading the declaration | Relying on the desktop screenshots, which are captured every run | A screenshot only catches a drifted design when a person opens it, and this one went unopened. Measuring two spans is the only way to catch a subset cut without its axes, which renders every weight identically and silently | No |
| 20 | The load harness warms up for five seconds before the clock starts | Measuring from cold, as it did | Every scenario, including the tile probe that does almost nothing, missed its target by a factor of ten while the median stayed under a millisecond: the first second of a cold process is one twentieth of a twenty-second run and lands exactly on the p95. The figures now describe a site that has been serving, which is what the targets are about. The cold start itself is written up in `benchmarks.md` because a deploy that takes traffic immediately will show it | **Review** if you would rather the targets include a deploy's first second |
| 21 | The harness refuses a run long enough to cross the lifted rate limit, with a sentence saying so | Letting it run and report the limiter's rejections as failures | The plan limiter's own ceiling is 10,000 a minute and the plan scenario injects 200 a second, so a sixty-second run fills the report with fast failures that read like the site falling over. A refusal that names the fix costs nothing and stops the next person chasing a ghost | No |
| 22 | The hero's picture is given `inline-size: 100%` alongside its auto inline margins | Removing the auto margins; sizing the SVG by hand | An auto inline margin on a grid item cancels its stretch and shrink-wraps it to its content, and an SVG with only a `viewBox` is 300px wide by default: together they had shrunk the kitchen table to 300px inside a 467px column at every width, which is the "tiny graphics" Rob's users noticed. The auto margins still centre it under the two-column breakpoint | No |
